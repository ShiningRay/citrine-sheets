# citrine-sheets 原生端口（CRuby + libui）操作与限制

```
bin/native            # 起原生窗口（需要 citrine / citrine-native 两个仓库与 libui gem）
rake native:test      # 原生端口测试（Memory 桩后端，不需要窗口）
```

前置：三个仓库放同级目录（或用 `CITRINE_ROOT` / `CITRINE_NATIVE_ROOT` 指定）；libui 动态库由
`libui` gem 提供（本机装在 asdf 的 Ruby 3.4.8 下）。视图与逻辑的分工见仓库根 README 的
「原生端口」一节；本文只写**操作方式**与**平台限制**（都来自真窗口实测）。

## 键盘/鼠标操作

全局键盘由**聚焦的自绘面板**转发（`Views::Grid` 的 `window_key`），所以下面这些键的前提是
焦点在网格上——正常启动后焦点就在网格（见「启动焦点」一节）。

| 操作 | 效果 |
|---|---|
| 方向键 | 移动选区（`Shift+方向` 扩展选区） |
| ⌘ + 方向键 | 跳到数据边缘（空白方向上的尽头） |
| 直接打字（字母/数字/符号） | 进入编辑态，后续字符追加进缓冲 |
| Enter | 非编辑态：编辑当前格；编辑态：提交并下移一行 |
| Tab / Shift+Tab | 非编辑态：右/左移一格；编辑态：提交并右/左移一格 |
| Esc | 编辑态：取消编辑；非编辑态：把操作提示写回状态栏 |
| Backspace | 非编辑态：以空缓冲进入编辑（提交后该格清空）；编辑态：删掉缓冲里最后一个字符 |
| Delete | 非编辑态：清空选区；编辑态：清空缓冲 |
| ⌘Z / ⌘⇧Z | 撤销 / 重做（编辑态下也生效） |
| ⌘B | 加粗（**只能加粗，不能取消**：`app/application.rb` 的既有共享缺陷，浏览器侧同样如此，本轮未改） |
| 点单元格 | 选中该格（同时把键盘焦点交给网格） |
| 点列头 A…Z | 选中整列 |
| 点行号 1…60 | 选中整行 |

**编辑态下的方向键什么都不做**（既不改缓冲也不移动选区）。这与浏览器侧一致——那边的方向键被
`<input>` 自己吞掉。看代码请以 `native/app.rb#edit_key` 为准（SHEETS-1c 的 D5 修掉了与该行为
不符的注释）。

## 平台限制（以及应用的绕法）

| 限制 | 表现 / 绕法 |
|---|---|
| **非 ASCII 键入到不了网格** | 适配层对非 ASCII 键不猜（libui 的 Key 字段只有 ASCII 等位字符，设计文档 2.3）。**中文请用鼠标点公式栏输入框，走系统 IME 输入**，再按「确认 ↵」按钮提交（原生 entry 拿不到 Enter，见下）。注意：这条绕法是按设计推断的可行路径，**本轮没有真验 IME 输入**（本机无法脚本化注入 IME 事件）。与启动取焦点的竞争见「启动焦点」一节的最后一条 |
| 原生 entry 拿不到 Enter/Tab/Esc | libui 的 entry 不暴露按键事件 → 编辑态的这些键由 area 侧补（`NativeApp#edit_key`）；公式栏那一行只能用鼠标点「确认 ↵ / 取消 Esc」 |
| 窗口不是 key window 时收不到键 | 框架在 `window_show` 之后调 `activateIgnoringOtherApps:`；焦点由 `AreaHandle#focus` 交给面板。启动时 `on_mount` 早于这两步，所以应用**排队重试**取焦点（见下） |
| 自绘面板没有滚轮事件 | 网格用 `scroll: true`（libui 的 NSScrollView 负责滚轮与滚动条）；`AreaHandle#scroll_to` 可把某块滚进视口（当前网格没用它） |
| `Painter#clip_rect` **现在报的是精确可见区** | 框架报 area 的 `visibleRect`（不含滚动条）：稳态实测 **579×667**（≈27 行）。SHEETS-1c 之前它报的是**控件自己的尺寸**（含滚动条位——修好 flex_grow 之后是 596×684，所以那时"偏大 ~18px"），D7 修复后稳态不再偏大。**唯一的例外是首帧瞬态**：视图还没布局完时第一帧仍可能报控件尺寸 596×684（框架注释里记录的同一条边界；本轮实测首帧 596×684、第二帧起 579×667）。应用**不按它裁剪**（按格裁剪），所以这条对我们只是信息，不影响正确性 |
| 窗口不能缩到比内容还小 | 最小尺寸由内容的自然尺寸决定（本轮实测：请求 420×300 实得 **1100×440**，非本应用可调） |
| `flex_grow` 的值被映射成 libui 的 stretchy（布尔） | `style: { flex_grow: 3 }` 与 `1` 等价：左右两栏各占一半，表达不出 3:2。表头/网格/检查器的**内部**布局不受影响 |

## 布局：根元素必须自己声明 `flex_grow: 1`（SHEETS-1c 的 D2 实测）

框架把组件树的根元素追加进"窗口内的根容器"时，stretchy 取的是**根元素自己的**样式。不声明的话：

- 根容器仍然填满窗口，但根元素只占内容的自然高度 → 窗口下半截全是空白；
- 里面所有 `flex_grow` 都分不到空间（子控件只能分父容器已经撑开的余量），
  网格视口被压到 596×**232**（约 8 行 × 6 列）。

`native/app.rb#view` 的顶层 `stack` 现在声明了 `style: { flex_grow: 1 }`，实测：

| 量 | 修复前 | 修复后 |
|---|---|---|
| 网格 NSScrollView（1240×860 窗口） | — | 596×684 |
| 网格可见区（去掉滚动条） | 578×214（≈8 行） | 579×667（≈27 行） |
| `Painter#clip_rect`（稳态） | 596×232（= 控件尺寸，偏大 ~18px） | **579×667**（= 精确可见区） |

`clip_rect` 这一行是 SHEETS-1d 按框架 D7 之后的现状改的：**曾偏大、现已精确**——它报的是
area 的 `visibleRect`（不含滚动条），只有在**首帧瞬态**（视图还没布局完）时才可能报回控件尺寸
596×684（本轮实测：首帧 596×684 → 第二帧起 579×667）。

结论：**滚动面板本身是能伸展的**（验收记录里"flex_grow 对滚动 area 不生效 / 框架限制"的说法
不成立）；真因是应用侧的根元素没声明 flex_grow，`flex_grow` 链断在根这一环。

## 启动焦点（SHEETS-1c 的 D1；SHEETS-1d 的 N1/N2）

`App#setup` 的顺序是 `mount_component`（跑 `on_mount`）→ `window_show` → 应用激活，所以
`on_mount` 里取焦点**必然失败**（那时 `[NSApp keyWindow]` 还是 nil）——修复前实测
`firstResponder` 停在公式栏的 `NSTextView` 上，方向键/⌘Z 到不了网格，打字落进公式栏又提交不了。

现在的做法（`Views::Grid#schedule_focus`）：

1. 挂载时先试一次（桩后端/已激活窗口这次就成功）；
2. 失败则每 250ms 重试，最多约 6s（实测屏幕刚唤醒时窗口变 key 要 ~4s）；
3. 到 ~1s 还没拿到就在公式栏提示「点一下网格即可用键盘」；之后**拿到焦点会自动把提示撤掉**，
   用户点了网格或键打进网格也会撤——提示不会撒谎；撤掉是**终态**，重试 tick 不会把提示
   重新点亮（SHEETS-1d 的 N1：修复前实测点掉提示后 +180~240ms 又回来）；
4. **用户一动手就"让位"**（SHEETS-1d 的 N2）：键打进网格 / 点了网格 / 在公式栏 entry 里改过
   文本（`on_change`）→ 立即停止重试、不再抢焦点。取焦点是抢占式的，重试窗口里用户可能在用
   公式栏输入框（上面那张中文输入的绕法），不让位的话下一个 tick 会把焦点从他刚点进去的
   输入框抢回网格——他得再点一次。

**与中文输入的竞争（诚实口径）**：libui 的 entry 不上报焦点/点击事件，应用侧唯一能观察到
「用户在输入框里」的痕迹是 **entry 的文本被改过**（第 4 条）。所以：只要你在输入框里打过字，
重试立刻让位；但如果只是**点了输入框、还没敲任何键**，而启动激活又恰好晚到（重试窗口内），
下一个 tick（≤250ms）仍可能把焦点拿回网格——再点一次输入框即可，之后不会再被抢（一次性）。
这条竞争只出现在"窗口变 key 要等好几秒"的机器状态上（正常激活时重试在第 1~2 个 tick 就结束，
人还没来得及点）。

SHEETS-1d 对 N1/N2 两条的真窗口 A/B（`CGEventPost` 真鼠标/真按键；探针 `/tmp/s1d/focus_flow.rb`，
`*_old` = 同一探针只把取焦点逻辑换回修复前实现）：

| 场景 | 修复前 | 现在 |
|---|---|---|
| focus 一直失败（能力缺口/误报，`MODE=stub`）：用户真鼠标点网格，提示已撤 | 提示在 +200ms 内**又回来**，重试定时器一直跑（att 10→19） | 提示不再出现（之后 1.45s 内 8 个采样点），定时器停、att 冻结 |
| 重试窗口内用户真鼠标点公式栏 entry 并打字（`MODE=latefocus`，前 15 次取焦点如实失败） | 下一次成功的那一 tick 把焦点抢回网格：FR `NSTextView` → **`areaView`** | FR 停在 `NSTextView`，att 冻结（15→15）、定时器停、提示撤掉 |
| 同上但**只点 entry、不输入**（`MODE=latefocus_nt`） | 被抢回网格 | **仍会被抢回网格**（上面那条诚实口径说的残余竞争，实测复现） |

网格键盘流回归（`MODE=normal`：启动后不点任何东西，真 OS 按键）：`ArrowDown`→A2、
`ArrowRight`→B2、打 `5`/`7`→缓冲 `57`、`Enter`→B2=57 且下移 B3、`⌘Z`→B2 回 120000、
撤销栈 0——六步全过（而修复前是"方向键/打字/⌘Z 全都到不了网格"）。

真窗口 A/B（同一个探针、同样灌入 OS 按键 `CGEventPost`，启动后不点任何东西）：

| | 修复前（`on_mount` 只试一次） | 修复后 |
|---|---|---|
| `firstResponder` | `NSTextView`（公式栏 entry 的 field editor） | `areaView`（网格面板的视图） |
| 方向键 | 应用收不到（选区不动） | `ArrowDown`/`ArrowRight`：A1 → A2 → B2 |
| 直接打字 | 应用收不到（字符进 entry，编辑态没开） | `5`、`7` → 编辑态、缓冲 `5` → `57` |
| Enter | 无反应 | 提交：B2=`57`、选区下移 B3、撤销栈 +1 |
| ⌘Z | 无反应 | 撤销：B2 回到 `120000`、撤销栈回 0 |

## 长值截断（SHEETS-1c 的 D3）

浏览器侧 `.cell` 是 `padding + overflow: hidden`，`.cell-text` 再叠 `text-overflow: ellipsis`。
原生侧现在同口径：每个有值的格先 `clip` 到**内容框**（左右各留 `PAD_X`），左对齐文本超宽时按
真度量砍到装得下再加「…」，右对齐的数字不加省略号（浏览器在右对齐溢出时裁掉的是行首，
`text-overflow` 只管行尾）。
